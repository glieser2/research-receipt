## Snapshot binding

`verify_evidence` independently fetches committed sources and stores one immutable snapshot per revision, including failure outcomes. Its identity binds policy, normalized spec (including catalog and criterion choices), typed submission, effective report content, order ID, revision, source order and material commitments. Every material is checked by original UTF-8 byte length and SHA-256. Failed, absent and empty materials have explicit representations rather than being silently omitted.

`evaluate` performs no source HTTP requests. It validates the complete stored snapshot against the current order/revision and submission commitments before any model judgment. The assessment binds that snapshot hash. The stable comparison covers each finding's criterion, type, validity, status, delivery status, support references, author-selected basis, complete-source scope and ordered field outcomes. Model explanation wording is outside that comparison. A matching aggregate verdict alone cannot pass.

Unknown disclosures are four-field structured inputs. Their visible wording derives from the buyer-locked catalog; author-written extra promises and unbound report paragraphs are rejected. The unknown branch checks all committed materials, including sources omitted from an author's factual basis. Factual/boundary judgments use explicit evidence-sufficiency semantics; author-selected basis is not labelled as a supporting citation. The policy change is v6, not a retrospective interpretation of a failed v5 finding.

## Recovery and write boundaries

Each revision has one source snapshot. Duplicate verification and evaluation before verification are rejected. A failed snapshot is retained; the user completes its assessment and genuinely changes evidence or research content before submitting a new revision. There is no abandon/retry shortcut. Content replay checks use effective text and scope, so changing only a label, title or claim type cannot bypass them.

The client persists transaction intent before sending, retains uncertain or pending outcomes, and resolves an EVM envelope through its exact protocol event. A confirmed error does not stand in for a successful VM return, and a finalized undetermined result does not count as accepted consensus. Error-case verification must also prove relevant final state did not change. Old revision snapshots and assessments remain immutable and are rechecked after correction.

Every live write freshly checks network identity, account, policy, the complete catalog and independently verified release source/address. Legacy contracts remain readable. Local draft preparation is available to visitors; submission still requires the locked author and a compatible release. A getter that merely claims policy v6 cannot establish deployed source identity.
